# 🧀 Pickeat SSE Server

실시간 식당 투표 서비스 'Pickeat'의 실시간 데이터 동기화를 담당하는 전용 SSE(Server-Sent Events) 서버입니다.

<br>

## 🏗 아키텍처 설계 및 기술 결정

**실시간 통신 기술 스택으로 SSE를 결정한 이유**

SSE는 HTTP 기반으로 동작하여 기존 인프라를 그대로 활용할 수 있어 WebSocket보다 복잡도가 낮고,
폴링 계열 방식보다 네트워크/메모리 효율이 높기 때문에 SSE를 선택했습니다.

**SSE 서버 분리**

WAS는 요청을 빠르게 처리하고 자원을 즉시 반환하는 단기 작업의 특징을 가지고 있고,
SSE는 클라이언트와의 연결을 장시간 유지하는 장기 점유형 특징을 가지고 있습니다.
두 서비스는 이처럼 상반된 특성을 가지고 있기에, 리소스 격리와 운영 효율을 위해
WAS와 SSE 서버를 분리하기로 결정했습니다.

**메시지 브로커 도입**

Redis Pub/Sub을 메시지 브로커로 활용하여 WAS와 SSE 서버 간 의존관계를 제거하고,
각 서버가 독립적으로 스케일 아웃할 수 있도록 설계했습니다. Kafka나 RabbitMQ 같은 별도 메시지 큐도
고려했으나 현재 요구사항 대비 운영 부담이 과하다고 판단하여 선택하지 않았습니다.

**동시 연결 처리 방식**

시스템 유지보수성을 위해 Webflux와 같은 비동기 방식 대신 가상 스레드를 선택했습니다.
비동기 방식은 성능 면에서 유리하지만 코드 복잡도가 높고 라이브러리 제약이 크지만,
가상 스레드는 성능 차이가 미미하면서도 기존의 익숙한 동기식 코드 흐름과 라이브러리를 그대로
사용할 수 있다는 이점이 있기 때문입니다.

## ⚡ 메시지 전송 전략

**메세지 전송 방식**

메시지 크기가 작고 복잡한 동기화 로직 없이 데이터 정합성을 보장할 수 있어
변경 점 전송 방식 대신 전체 상태 전송 방식을 선택했습니다. 또한
이를 통해 최신 메시지만 전달되는 구조로 성능 이점도 확보할 수 있었습니다.

**메세지 누락 대비**

재연결 시에는 전체 상태 조회 API로 동기화하고, 불안정한 네트워크로 메시지가 일부 누락된 경우에는
최신 메시지로 상태를 덮어씌워 정합성을 유지합니다. 또한 일정 시간 동안 메시지가 도착하지 않으면
전체 상태 조회 API를 통해 누락을 감지하고 동기화합니다.

**메세지 순서 역전 대비**

메시지마다 시퀀스 번호를 부여해 순서를 정의하고, 이전 시퀀스의 메시지는 무시하는 방식으로
순서 역전을 방지했습니다. 분산 환경에서도 순서가 올바르게 보장되도록 Redis INCR 기반의
전역 시퀀스를 적용했습니다.

## 🛠️ 트러블슈팅

**Backpressure 제어 문제**

전체 상태 전송 방식 특성상 버퍼에 여러 메시지가 대기 중이더라도 최신 메시지만 전송하면 충분하기에, 복잡한 버퍼 큐
대신 단일 슬롯에 최신 데이터만 유지하는 LWW 전략을 도입했습니다. 또한 전송 지연이 임계치를 초과하면
해당 커넥션을 불안정하다고 판단해 연결을 끊고 클라이언트가 재연결할 수 있도록 설계했습니다.

**슬롯 관련 스레드 동시성 문제**

슬롯에 데이터를 쓰는 스레드와 읽어서 전송하는 스레드가 분리되어 동시성 문제가 발생했습니다.
AtomicBoolean과 AtomicReference의 CAS 연산을 활용해 락 없이 동시성 문제를 해결했습니다.

**가상 스레드 Pinning 문제**

동시성 제어를 위해 synchronized 블록 대신 Atomic 라이브러리의 CAS 연산을 활용함으로써
가상 스레드가 캐리어 스레드에 고정되는 Pinning 문제를 방지했습니다.

**Thundering herd 문제**

재연결 시 0~5초 사이의 랜덤 지터를 적용해 요청을 분산시키고, 재연결 실패 시에는 대기 시간을
점진적으로 늘리는 백오프 정책을 도입했습니다. 또한 서버 시작 시 대량의 클라이언트가 동시에
연결을 시도하는 상황에 대비해 서버 측 연결 클라이언트 수를 제한하는 방향으로 리펙토링을 계획 중입니다.

**HTTP 버전 및 캐시 설정**

HTTP/1.0은 Keep-Alive를 지원하지 않기 때문에 HTTP/1.1로 업그레이드했습니다.
또한 Nginx 버퍼에 메시지가 갇히지 않도록 버퍼를 비활성화하고,
캐싱으로 인해 최신 메시지가 전송되지 않는 문제를 방지하기 위해 캐시 설정도 비활성화했습니다.
